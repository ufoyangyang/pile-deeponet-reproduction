# 其他应用方向

这套框架的核心是**"用少量可测输入 + 物理约束，实时预测一个不可测的内部场"**。
凡是满足这三点的场景，都可以直接迁移。

---

## 1. 换电池化学体系（改动最小）

论文 Appendix E 已经给出 NMC 软包的整套参数
（`rho=2201, cp=995, k=0.84, E=1.54e5, A=2.244e12, H=4.24e5, W=530, Gas0=0.25 g`），
在 `config.py::PhysicsConfig` 里替换后，`scripts/make_dataset.py` 一条命令即可生成新数据集。

可迁移的体系与需要改动的地方：

| 体系 | 需要改 | 备注 |
| --- | --- | --- |
| NMC / NCA 软包 | 上面 8 个参数 + 几何 | 产气量、峰值温度与 LFP 差别很大（NMC 更剧烈） |
| 钠离子 | 动力学三件套 `E, A, H` | 目前公开的热失控数据少，需要实验标定 |
| 固态电池 | 增加界面电阻热项 | 产气机制不同（可能几乎不产气），`Gas0→0` 时压力通道失效 |
| 大圆柱（4680/4695） | `radius, height, n_r` | 径向温差更显著，1D 假设更成立 |
| 方形/软包 | 需要 2D 或各向异性 `k` | 1D 径向不够，改成 `physics.py` 的 2D 版本 |

## 2. 从电芯到模组 / 电池包

论文是**单电芯**尺度。工程上真正关心的是**热蔓延（cell-to-cell propagation）**：

* **集总 + 算子混合**：每个电芯仍用本框架的算子预测自身 T/压力，
  电芯之间用热阻网络（或 1D 导热）耦合。算子负责"单芯非线性"，网络负责"系统拓扑"。
* **图神经网络 + DeepONet**：把电芯当节点、导热路径当边，branch 输入是邻居状态，
  这样对任意拓扑（不同串并联数）都能泛化。
* **热蔓延预警**：预测目标从"单芯峰值"改为"相邻电芯达到触发温度的时间差"，
  `t_d` 的选取要相应提前（可能要 5–10 min）。

---

## 3. 不同触发方式

论文只考虑**外部加热**（`S(c)·h_heater`）。其他触发方式的改动：

| 触发 | 物理改动 | 数据需求 |
| --- | --- | --- |
| 针刺 | 局部内短路热源 `Q_ISC(x,t)`，需要 2D/3D | 针刺实验数据标定热源分布 |
| 过充 | 增加副反应热 + 锂沉积 | 充电曲线与电压数据 |
| 外短路 | 焦耳热 `I²R` 与 SOC 相关 | 电流/内阻数据 |
| 内短路 | 随机位置 + 随机阻值 → 更适合做**不确定性预测** | 需要大量仿真场景 |

## 4. BMS 在线部署（最现实的落地路径）

论文报告的推理时延是 **4.96 ms（A100）/ 45.23 ms（边缘端）**，而模型的输入只需要：

* `u1`：冷却能力（可从冷却回路工况查表）
* `u2`, `u3`：**表面温度历史**——BMS 本来就在采样（论文实验用 10 Hz 热电偶）
* 不需要任何内部温度、压力、气体传感器

落地要点：

1. **模型压缩**：`q=300 → 96`、`hidden=100 → 64` 只损失约 1–2 个百分点精度，
   参数量从 1.24 M 降到约 0.1 M，可上 MCU/DSP。
2. **滑窗推理**：每 30 s 更新一次输入，每 1 s 前向一次刷新预测曲线（成本可忽略）。
3. **早期触发**：`t_thr=120 °C` 是论文的判据；工程上可降到 80–100 °C 换取更长预警时间，
   代价是 `u2` 窗口信噪比下降。
4. **失效降级**：当传感器缺失时，用最近一次预测值 + 物理模型外推；
   `u1` 缺失时固定为标称值（对精度影响最小，因为 `u1` 只影响冷却项）。

## 5. 冷却系统设计与反向优化

把 `u1`（冷却能力）当作**连续输入**而不是离散集合 {7,10,13,16,19}：

* 训练时 `h_cool` 在 [5, 25] 上均匀采样，算子就变成 `(h_cool, 历史温度) → 峰值温度/时间` 的连续映射。
* 由于算子网络的前向是毫秒级，可以直接做**反解**：
  "要让峰值不超过 150 °C，在 2600 s 升温工况下最小需要多大换热系数？"
  ——梯度下降或二分搜索几百次前向即可（< 1 s）。
* 论文 Sec. 3.7 的"h=100 W/(m²K) 在预测峰值时刻启动"就是这条路径的雏形；
  把它做成连续优化就是冷却系统选型工具。

## 6. 传感器布局与可观测性

论文用显著性 `I_T = |∂T̂/∂T̂_F|` 和隐特征 PCA 说明"哪些历史片段重要"。可以进一步：

* 用 `∂T_surface/∂T_center` 的灵敏度找**最能代表内部温度的表面位置**（多点热电偶选位）。
* 用 `u2` 各时间步的梯度幅值决定**采样频率**（例如最后 300 s 加密到 1 s）。
* 用信息论指标（互信息）选择传感器数量与位置，替代经验布点。

## 7. 少样本迁移到新电芯/新工况

论文的数据稀缺实验（84→24 工况，PILE 总 WAPE 4.13→4.97，而纯数据模型 5.33→6.68）
说明：**物理约束在小数据下更值钱**。工程上可以：

1. 用仿真数据预训练（本仓库 `make_dataset.py`，5 s 生成 124 工况）；
2. 用 3–5 次真实热失控实验做**微调**（只解冻最后一层 + 输出偏置）；
3. 用**域适应**（如 CORAL/MMD）对齐仿真与实验的特征分布，解决 sim-to-real gap。

## 8. 不确定性量化与安全裕度

安全场景不能只给点预测。论文用 100 次蒙特卡洛（对输入加 σ=0.5/1.0 °C 噪声）给出
峰值 95% 区间宽 16.3 °C / 63.2 °C。更工程化的做法：

* **Deep Ensemble**（5–10 个模型）：区间更可靠，推理成本 ×5（仍是毫秒级）。
* **MC-dropout**：成本几乎不变，但区间偏窄。
* **Conformal prediction**：用验证集校准，给出有统计保证的区间。
* 输出层直接预测 `(μ, log σ²)`（异方差回归），适合峰值时刻这种重尾目标。

## 9. 与其他模型的互补

| 组合 | 作用 |
| --- | --- |
| 等效电路模型（ECM）+ 本算子 | ECM 负责电学量（SOC/SOH），算子负责热失控段 |
| 电化学模型（P2D/SPM）+ 本算子 | 电化学模型算正常工况，算子接管滥用工况（避免 P2D 在高温失效区数值发散） |
| CFD/3D FEM + 本算子 | 3D 仿真做"高保真标签"，算子做实时代理（digital twin 的标准套路） |
| 卡尔曼滤波 / EnKF + 本算子 | 用实测表面温度做**数据同化**，在线修正预测轨迹 |

## 10. 更远的场景

* **储能电站**：机柜级热失控预警，输入是舱内温度 + 空调工况；输出是"哪个簇会先进入热失控"。
* **快充策略优化**：把充电电流曲线参数化，用算子网络预测峰值温度作为约束，做充电时间最小化。
* **电池全生命周期**：老化后的 `E, A` 变化 → 用少量在线数据更新物理参数，
  算子网络不变（这是"物理参数化 + 网络代理"的最大好处）。
* **多物理场扩展**：力-热-电-气耦合（产气导致壳体膨胀、喷发），
  把 `Gas` 从标量扩展成空间场，`P` 由局部状态方程给出。
* **跨设备迁移**：把 `u1` 扩展成"环境温度 + 风速 + 冷却液流量"的多维输入，
  同一网络覆盖不同散热条件。

## 11. 工程落地的几个现实约束

1. **标签只能来自仿真**：真实热失控实验成本高、破坏性强，因此 sim-to-real 校准是核心风险。
2. **输入时延**：`u2` 需要 900 s 历史，意味着电芯上电后至少 15 min 才能给出首个预测；
   冷启动阶段应退回纯物理模型。
3. **分布外工况**：论文测试集 3（更快升温）WAPE 是测试集 1 的 6.8 倍（8.75% vs 1.15% AREP）。
   部署时必须做 **OOD 检测**（例如用隐特征的马氏距离），超阈值就降级为"高不确定"。
4. **模型漂移**：电芯老化、批次差异会改变 `E, A, H`；建议每季度用新数据重标定物理参数，
   网络权重可以冻结。
